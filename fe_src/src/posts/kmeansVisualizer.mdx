<Lang locale="en">

One of the fastest ways to actually understand a machine-learning algorithm is to build it
from scratch and then *watch it run*. So I wrote KMeans clustering in plain NumPy — no
scikit-learn — and wrapped it in a visualizer where you can drop the centroids, step through
Lloyd's iterations one at a time, and see the clusters snap into place.

This started as a course assignment (a Flask app that rendered matplotlib frames). For this
post I pulled the algorithm out, rebuilt it as a small **stateless JSON API** in this site's
backend, and render the whole thing on an HTML canvas — so the demo below is the *real*
algorithm running live, not a recording.

</Lang>

<Lang locale="ko">

머신러닝 알고리즘을 제대로 이해하는 가장 빠른 방법 중 하나는 직접 처음부터 구현하고 *돌아가는 걸
눈으로 보는 것*이다. 그래서 KMeans 클러스터링을 scikit-learn 없이 순수 NumPy로 짜고, 센트로이드를
직접 찍고 Lloyd 반복을 한 스텝씩 밟아가며 클러스터가 자리를 잡는 걸 볼 수 있는 시각화 도구로 감쌌다.

### The algorithm — Lloyd's iteration

KMeans splits points into _k_ clusters by repeating two steps until nothing moves. **Assign**
every point to its nearest centroid:

</Lang>

<Lang locale="ko">

### 알고리즘 — Lloyd 반복

KMeans는 두 단계를 아무것도 안 움직일 때까지 반복하며 점들을 _k_개의 클러스터로 나눈다. 먼저 모든
점을 가장 가까운 센트로이드에 **할당(assign)**:

</Lang>

$$
c_i = \arg\min_j \lVert x_i - \mu_j \rVert^2
$$

<Lang locale="en">

then **update** each centroid to the mean of the points assigned to it:

</Lang>

<Lang locale="ko">

그다음 각 센트로이드를 자기에게 할당된 점들의 평균으로 **갱신(update)**:

</Lang>

$$
\mu_j = \frac{1}{|C_j|} \sum_{x \in C_j} x
$$

<Lang locale="en">

That's it. Assign, update, assign, update — it always converges, though _where_ it converges
depends entirely on where the centroids start. Which is the interesting part.

</Lang>

<Lang locale="ko">

그게 전부다. 할당, 갱신, 할당, 갱신 — 항상 수렴한다. 다만 _어디로_ 수렴하느냐는 센트로이드가 어디서
출발했느냐에 전적으로 달려 있다. 그게 재미있는 지점이다.

</Lang>

### Four ways to start

Initialization is where KMeans lives or dies, so the demo lets you pick among four:

- **Random** — pick _k_ data points at random. Simple, but unlucky picks give bad clusters.
- **Farthest First** — pick the point farthest from the ones chosen so far. Spreads centroids
  out, but chases outliers.
- **KMeans++** — pick the next centroid with probability proportional to its squared distance
  from the nearest existing one. The sweet spot: spread out, but robust to outliers.
- **Manual** — click _k_ points yourself and watch how your choice steers the result.

</Lang>

<Lang locale="ko">

### 시작하는 네 가지 방법

KMeans는 초기화에서 성패가 갈린다. 그래서 데모에서 네 가지 중 고를 수 있게 했다:

- **Random** — _k_개의 데이터 점을 무작위로 고른다. 단순하지만 운 나쁘면 클러스터가 엉망이 된다.
- **Farthest First** — 지금까지 고른 점들에서 가장 먼 점을 고른다. 센트로이드를 넓게 퍼뜨리지만
  이상치(outlier)를 쫓아간다.
- **KMeans++** — 가장 가까운 기존 센트로이드와의 거리 제곱에 비례하는 확률로 다음 센트로이드를
  고른다. 넓게 퍼지면서도 이상치에 강한, 가장 균형 잡힌 방법.
- **Manual** — _k_개의 점을 직접 클릭해서, 그 선택이 결과를 어떻게 끌고 가는지 본다.

</Lang>

### How it's wired

The original assignment computed each frame on the server with matplotlib and returned PNGs,
leaning on global state and files on disk — fine for one person, but it would fall apart with
two people clicking at once. For this site I rewired it:

- **`be_src/` (FastAPI)** — the NumPy algorithm, exposed as two stateless endpoints:
  `GET /api/kmeans/dataset` and `POST /api/kmeans/run`. A single `run` call computes the
  *whole* Lloyd's sequence and returns it as JSON — no server state, no disk, safe for many
  visitors at once.
- **React canvas** — the component fetches that step list and draws each frame itself, so
  stepping and animating are instant and the server does the math exactly once.
- **nginx** proxies `/api` to the backend container; in dev, Vite does the same. The demo above
  is talking to that backend right now.

`be_src/` is the general backend for this site, so this is just its first feature — adding the
next one is a new router.

</Lang>

<Lang locale="ko">

### 어떻게 연결돼 있나

원래 과제는 매 프레임을 서버에서 matplotlib로 그려 PNG로 돌려줬고, 전역 상태와 디스크 파일에
의존했다. 혼자 쓸 땐 괜찮지만 두 명이 동시에 클릭하면 무너진다. 이 사이트에 올리면서 다시 배선했다:

- **`be_src/` (FastAPI)** — NumPy 알고리즘을 두 개의 무상태 엔드포인트로 노출:
  `GET /api/kmeans/dataset`, `POST /api/kmeans/run`. `run` 한 번이 *전체* Lloyd 시퀀스를 계산해서
  JSON으로 반환한다 — 서버 상태도, 디스크도 없어서 여러 명이 동시에 써도 안전하다.
- **React 캔버스** — 컴포넌트가 그 스텝 리스트를 받아서 프레임을 직접 그린다. 그래서 스텝/애니메이션이
  즉각적이고, 서버는 계산을 딱 한 번만 한다.
- **nginx**가 `/api`를 백엔드 컨테이너로 프록시한다(개발 땐 Vite가 같은 일을 한다). 위 데모는 지금
  바로 그 백엔드와 통신하고 있다.

`be_src/`는 이 사이트의 범용 백엔드라, KMeans는 그 첫 번째 기능일 뿐이다 — 다음 기능은 라우터 하나를
더 붙이면 된다.

### What I'd do differently

The clustering is exact, but the visuals are deliberately minimal. Next I'd add a live
"inertia" (within-cluster sum of squares) readout so you can _see_ KMeans++ converge faster,
overlay Voronoi regions, and let you scrub the iteration timeline instead of only stepping
forward. The algorithm code is on GitHub:

- **GitHub:** [the original assignment repo](https://github.com/digitaldna01/jhonglee-assignment-2)

</Lang>

<Lang locale="ko">

### 다르게 해보고 싶은 점

클러스터링 자체는 정확하지만 시각화는 의도적으로 최소한이다. 다음엔 클러스터 내 제곱합(inertia)을
실시간으로 표시해서 KMeans++가 더 빨리 수렴하는 걸 _눈으로_ 보게 하고, Voronoi 영역을 겹쳐 그리고,
앞으로만 스텝하는 대신 반복 타임라인을 자유롭게 오갈 수 있게 하고 싶다. 알고리즘 코드는 GitHub에 있다:
