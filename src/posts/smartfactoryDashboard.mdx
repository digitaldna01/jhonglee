### Ideas

반도체 및 디스플레이 공장은 MES(Manufacturing Execution System)를 기반으로 운영된다. 하지만 대부분의 MES 화면은 정보가 빽빽하고, 시각적으로 무겁고, 전형적인 "엔터프라이즈 소프트웨어" 느낌이 강했다. 그래서 만약 공장 제어 인터페이스를 잘 만든 B2B SaaS 제품처럼 설계한다면 어떤 모습일지 한번 탐구해보고 싶었다.

컨셉은 **FabOS** — 디스플레이 패널 생산을 위한 스마트 팩토리 인텔리전스 플랫폼. 하나의 캔버스 안에 세 개의 핵심 패널을 배치했다.

- 중앙의 인터랙티브 **공정 맵** 유리 기판 투입 → 세정 → 증착 → 노광 → 검사 → 셀 조립 → QC
- 왼쪽의 드래그 가능한 **AI 에이전트 / 워크플로우 패널**
- 오른쪽의 에이전트 실행 일정을 관리하는 **Notion 스타일 일정 캘린더**

시각적 레퍼런스는 항공 화물 대시보드와 클린룸 제어 패널에서 가져왔다. 밝은 회색 배경, 둥근 카드, pill 형태의 탭, 최소한의 검정 포인트. 산업적이지만 차분한 느낌을 목표로 했다.

### Step 1 — Claude Chat에서 디자인 시스템 만들기

### Step 2 — Claude Design에 디자인 시스템 설정하기

디자인 시스템을 정의한 뒤, Claude Design을 열고 Design System 탭에 내용을 입력했다.

**Company name / Design system name:**

```text
FabOS Design System — Smart Factory Intelligence Platform
A light industrial SaaS design language for display panel manufacturing operations.
Inspired by aircraft freight control and clean-room precision interfaces.
```

Notes field
이 내용은 해당 탭에서 생성되는 모든 결과에 계속 적용된다.

```text Fonts: Inter (300/400/500/600) + DM Mono (400/500) via Google Fonts.
Colors: Page bg #F5F5F2, card surface #FFFFFF, primary text #1A1A1A, secondary
#888888. Status — Green #10B981 (pass/run), Amber #F59E0B (hold/warn), Red
#EF4444 (alarm/fault), Blue #3B82F6 (processing/info). Violet #7C3AED reserved
exclusively for AI agents and orchestration.

Style rules: No dark backgrounds. No gradients. No neon.
Cards use 1px solid #E8E8E4 border, 12–16px radius.
Navigation tabs are black pill (#1A1A1A fill, white text) on off-white page.
All data values (lot IDs, timestamps, sensor readings) use DM Mono.
Section labels are 10px uppercase #888 with 0.1em letter-spacing.
Black fill (#1A1A1A) is reserved for primary action buttons only.
Chips always use: colored dot + pastel background + dark matching text.

Mood: Clean-room precision. Calm, trusted, technical.
Like aircraft avionics — zero noise, total operational clarity.

```

Notes field에 디자인 시스템을 한 번 넣어두면, Claude Design은 개별 프롬프트를 받기도 전에 전체 시각 언어를 이해한 상태로 출발한다. 이후 생성되는 모든 컴포넌트가 폰트, 컬러, spacing 규칙을 자연스럽게 상속받는다.

### Step 3 — 대시보드 디자인 생성하기

디자인 시스템을 불러온 뒤, Claude Design에 세 개의 패널로 구성된 대시보드 레이아웃 생성을 요청했다. 좋은 결과를 얻기 위한 핵심은 단순히 "어떻게 보일지"가 아니라, 각 패널이 "어떻게 동작해야 하는지"를 구체적으로 설명하는 것이었다.

프롬프트에는 다음 내용을 포함했다.

```text
- 중앙 공정 맵은 정적인 일러스트가 아니라 인터랙티브 운영 캔버스여야 한다. 설비 모듈 선택, lot count badge, alarm chip, status indicator를 포함한다.
- 왼쪽 에이전트 패널은 defect analysis agent, recipe validation, equipment health check, WIP delay prediction 등 드래그 가능한 workflow card를 포함한다.
- 오른쪽 일정 패널은 Notion Calendar 스타일의 orchestration view로 구성한다. day/week control, color-coded event block, drag-and-drop scheduling을 지원한다.
```

4~5분 뒤, Claude Design은 FabOS 디자인 언어를 충실히 반영한 고충실도 mockup을 뱉어냈다. pill navigation, off-white background, 중앙의 둥근 process module, 왼쪽의 violet accent agent card, 오른쪽의 깔끔한 calendar event block까지 모두 갖춰진 형태였다.

### Step 4 — 컴포넌트 디테일 다듬기

몇몇 컴포넌트는 추가적인 작업이 필요했다.

**Process map modules**
첫 번째 버전의 공정 단계는 단순한 라벨 박스 수준이었다. 그래서 각 module에 status indicator dot, WIP lot count badge, subtle selection highlight state가 필요하다고 추가로 요청했다. 두어 번 바이브 디자인을 거치자, 공정 모듈은 진짜 설비 cell처럼 느껴지기 시작했다 — 선택 가능하고, 빠르게 스캔할 수 있으며, 정보 밀도는 높지만 시각적으로 복잡하지 않은 형태로.

**AI agent cards**
Violet accent의 톤을 잡는 데에는 몇 번의 시도가 필요했다. 목표는 AI 카드가 일반 workflow card와 명확히 구분되면서도 전체 light palette를 해치지 않는 것. 최종적으로는 부드러운 #EDE9FE 배경, #7C3AED 텍스트, violet left-border accent 조합으로 정리했다. AI 요소라는 점은 분명히 드러나지만, 차분한 분위기는 그대로 유지된다.

**Schedule calendar**
가장 까다로웠던 패널은 calendar였다. 초기 버전은 영락없는 Gantt chart 모양이었다. 대부분의 grid line을 제거하고, time slot의 vertical padding을 늘리고, scheduled workflow를 bar가 아니라 둥근 card 형태로 바꿨다. 그제서야 Notion Calendar의 event 표현 방식에 가까워졌다.

### Step 5 — Claude Code로 넘기기

디자인이 어느 정도 완성된 뒤, Claude Design의 Share to Claude Code 기능을 사용했다. 이 기능은 design context — component structure, spacing, color values, font choices 등 — 를 Claude Code 세션으로 그대로 넘겨준다.

<div className="grid grid-cols-1 gap-4 not-prose">
  <img
    src="/images/posts/smartfactory-dashboard/design-to-code.png"
    alt="dashboard-1.png"
  />
</div>

실제 구현 프롬프트는 비교적 단순했다. *Copy Command*로 Claude Code CLI에 붙여넣기만 하면 된다!

```text
Fetch this design file, read its readme, and implement the relevant aspects of the design. https://api.anthropic.com/v1/ design/h/v2DIWzOGP2iBDp_4djgL_w?open_file=Smart+Factory+0S.html
Implement: Smart Factory OS.html
```

Claude Design에서 디자인 파일을 임시로 올리고 Claude Code가 읽어와 구현하는 방식이다.

Claude Code는 컴포넌트 구조를 scaffold하고, selected module, detail panel view, calendar view toggle 같은 interactive state를 연결해주었다. Claude Design에서 넘어온 design token도 기반 스타일로 자동 적용됐는데, color variable, border radius, font weight 등이 예상보다 훨씬 깔끔하게 반영되었다.

왼쪽 agent panel에서 calendar로 드래그 앤 드롭하는 기능은 UX를 맞추기 위해 약간의 추가 prompting이 필요했다. 다만 interaction을 명확하게 설명해주자 Claude Code는 기본 로직을 무난히 처리했다.

예를 들어 다음과 같이 설명했다.

```text
dragging a card from the left panel and dropping it onto a calendar time slot
should create a new scheduled event block with the card's title, category color,
and a default 30-minute duration.
```

이렇게 원하는 동작을 구체적으로 설명하면, Claude Code는 그에 맞는 상태 관리와 이벤트 처리 로직을 알아서 구성해주었다.

### 최종 대시보드 모습

라이브 데모는 [factory-dashboard-demo](https://digitaldna01.github.io/factory-dashboard-demo/)에서 확인할 수 있다. GitHub Pages 배포까지 Claude Code에서 명령어 한 줄로 끝났다. 최종 결과물은 세 개의 패널로 구성되어 있다.

- **Center (공정 맵)**: 유리 기판 투입부터 final QC까지 이어지는 디스플레이 패널 생산 흐름을 보여준다. 각 공정 모듈은 클릭 가능하며, WIP count, equipment status, active alarm 등을 확인할 수 있다.
- **Left (AI Agent 패널)**: agent와 workflow card가 배치되어 있다. Agent-driven action에는 violet accent를, 일반 workflow에는 blue 계열을 사용했다.
- **Right (Schedule)**: Notion 스타일의 calendar가 배치되어 있다. Scheduled run은 깔끔한 event block 형태로 표시되며, workflow category에 따라 색상이 구분된다.

전체 인터페이스는 처음 레퍼런스로 삼았던 항공 화물 대시보드의 감성을 공장 운영 화면에 옮겨놓은 형태에 가깝다. 밝고, 차분하고, 기술적이며, 신뢰감 있는 화면을 목표로 했다.

### 잘 작동했던 점

**Design system notes field가 핵심이었다.**
Claude Design에서 이 부분만 잘 설정해두면, 이후의 모든 생성 결과가 올바른 방향에서 시작된다. 매번 폰트나 컬러를 다시 설명할 필요가 없다 — Claude가 이미 디자인 시스템을 이해한 상태이기 때문이다.

**Claude Design → Claude Code 핸드오프가 예상보다 자연스러웠다.**
Export된 design context에는 color와 spacing 정보가 충분히 담겨 있어서 Claude Code가 임의로 추측해야 할 부분이 적었다. "이렇게 보여야 한다"와 "이걸 코드로 구현한다" 사이의 간극이 일반적인 Figma-to-developer 핸드오프보다 훨씬 좁게 느껴졌다.

**긴 프롬프트보다 구체적인 프롬프트가 더 효과적이었다.**
전체 분위기만 장황하게 설명한 프롬프트는 애매한 결과를 만들 가능성이 높았다. 반면, "공정 모듈을 클릭하면 lot status, active recipe, assigned agent가 포함된 slide-in detail panel이 열린다"처럼 구체적인 interaction을 짧게 설명한 프롬프트가 훨씬 좋은 결과를 만들었다.

---

### 다르게 해보고 싶은 점

현재 process map은 data-driven이라기보다 여전히 illustrative한 성격이 강하다. 실제 운영에 쓰려면 각 process module의 running, alarm, idle 상태를 MES backend에서 받아오는 live WebSocket data로 제어하는 구조가 필요할 것이다. 이 부분은 다음에 Claude Code와 다시 다뤄볼 만한 주제다.

Drag-and-drop scheduling에도 아직 edge case가 남아 있다. event overlap이나 multi-day workflow 같은 케이스는 실제 공장 운영자에게 배포하기 전에 좀 더 세밀한 product thinking이 필요해 보인다.

---

### 전체 워크플로우 요약

```text
1. Claude Chat
   → 디자인 시스템 정의: colors, fonts, tokens, mood
   → 디자인 시스템 reference widget 생성

2. Claude Design — Design System Tab
   → company name + notes 입력
   → 이후 모든 generation에 디자인 시스템 적용

3. Claude Design — Generate
   → 각 패널의 interaction detail을 구체적으로 prompt
   → process map, agent cards, calendar를 반복적으로 개선

4. Claude Design — Share to Claude Code
   → design context를 Claude Code session으로 export

5. Claude Code
   → React component structure scaffold
   → selection, drag-drop, view toggle 등 interactive state 구현
   → exported context 기반 design token 적용

6. Deploy
   → Live demo 배포
```

첫 프롬프트부터 동작하는 데모까지, 걸린 시간은 대략 반나절.

---

이 툴체인은 이런 유형의 작업에 꽤 실용적이었다. 특히 복잡하고 데이터가 많은 B2B 인터페이스, 디자인 언어가 정교해야 하고 컴포넌트 interaction이 명확해야 하는 운영형 SaaS 화면에서 강점이 두드러졌다. Claude Chat → Claude Design → Claude Code로 이어지는 흐름은 디자인과 엔지니어링 사이에서 흔히 발생하는 소통 비용을 상당히 줄여줄 것 같다 <span className="line-through">다만 Claude에 쓴 $110은 별도다.</span>

MES 대시보드, 물류 control panel, 혹은 운영 중심의 SaaS 제품을 만들고 있다면, 위와 같은 접근 방식이 꽤 괜찮은 출발점이 될 수 있다.
